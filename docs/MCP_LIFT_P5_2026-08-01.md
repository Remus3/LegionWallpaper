# P5 - memi as a one-shot UI audit - RESULT: DO NOT ADOPT (2026-08-01)

Phase P5 of `mcp-lift-phases` (BACKLOG). The dive raised memi 4 -> 6 on three
corrections to the triage's summary (static over source, no key for the first
audit, Windows explicitly supported) and set a single adoption test:

> Run it against both pages and adopt only if it catches something the 5-phase
> ritual missed.

**It caught nothing the ritual missed. Its one finding is a false positive that
fires on the fix it recommends, and its headline scores are unbacked.** Not
adopted, in any role.

## The package is not the one the name implies

`npm view memi` returns **version 0.0.8**, an unrelated package by a different
author. The tool the dive scored is **`@memi-design/cli` 2.7.4** - a scoped
package that a bare `npx memi` would not reach. Running the obvious command
would have executed a stranger's package and, if it had produced any output at
all, attributed it to the tool under evaluation.

Verified before executing anything: `@memi-design/cli` 2.7.4, MIT,
`engines.node >=20` (this box runs 24.15.0), published 2026-08-01,
`bin.memi -> dist/index.js`, integrity
`sha512-6bksTLz+3YRV0QgH69lWPQ2EVPgKlvnTdrx9MH0F69GhRVfwLqDKf6na8D8qKcV5YafMF+cMdOS3DAX4xQEQvw==`.
It does declare `@anthropic-ai/sdk` as a dependency, so the dive's "no key"
claim was worth testing rather than trusting - it held: `diagnose` and
`craft audit` both ran to completion with no key set.

## What it reported, and what is actually in the files

Both pages are hand-written HTML with a `:root{}` custom-property block. Neither
contains Tailwind - `grep -c -i tailwind` is **0** in both.

| | `web/monitor.html` | `web/rundash.html` |
|---|---|---|
| memi score | 49/100 | 38/100 |
| memi verdict | needs a design-system pass | needs a design-system pass |
| memi `tailwindClasses` | 29 | 175 |
| actual Tailwind classes | **0** | **0** |
| memi `cssVariables` | 10 | 15 |
| memi `hexColors` | 1 | 0 |
| actual unique hex literals | **11** | **10** |
| memi issues found | 1 (MEDIUM) | **0** |

Three independent failures in that table:

**1. The one finding fires on compliance.** `color.raw-hex`, "Raw colors are
leaking into UI code", recommendation "Move recurring colors into CSS variables
or Tailwind theme tokens". Its own cited evidence is
`web/monitor.html:9`, excerpt `--bg:#0a1428;--pa...` - the CSS custom-property
declaration block. Every hex in that file appears exactly once, inside that
block, and every consumer references `var(--...)`. The page is already in the
state the recommendation asks for, and the finding is raised BY that state.
Acting on it would mean deleting the token definitions.

**2. The colour metric is wrong in both directions.** monitor.html has 11 unique
hex literals and is reported as 1; rundash.html has 10 and is reported as 0. A
"0 raw colours" reading on a file with 10 of them is the shape that would let a
real regression through if this were wired into CI.

**3. The scores are not evidence.** rundash.html scores **38/100 with zero
findings** and four of six dimensions listed as unassessed. monitor.html, which
has MORE raw hex and FEWER CSS variables, scores **49** - eleven points HIGHER
than the cleaner file. And the same rundash.html file scores **81/100** under
`craft audit` against **38/100** under `diagnose`, with all seven craft
dimensions reported "Not assessed by static scan". Two numbers 43 points apart
on one unchanged file, neither backed by a finding.

## The one idea worth keeping

memi labels its unassessed dimensions explicitly - "unverified, not
verified-good" - rather than letting silence read as a pass. That is the right
instinct and it is the same distinction LW already ships: the dashboard's third
chip state is NOT OBSERVED, and `slice_orchestrator`'s verdict history treats an
absent record as unobserved rather than clean. Nothing to lift; LW got there
first.

## Verdict

**DO NOT ADOPT** - not as a gate, not as an advisory one-shot, not in CI. The
`enforce-design-ci` mode is specifically ruled out: a gate whose colour counter
reads 0 on a file with 10 hex literals, and whose score moves 43 points on an
unchanged file depending on subcommand, would be a false-green generator wired
directly into the thing LW built `claimed_green_gate.py` to prevent.

The 5-phase UI-audit ritual (STRUCTURE / TYPOGRAPHY / HIT-TARGETS / ASCII /
HIERARCHY) stands unchanged. The dive's own reservation was right and turns out
to be the whole story: the ritual's judgement half is not automatable, and the
part memi can do statically, it did wrong here.

Do-not-redo:

- Do NOT `npx memi` - that is a different package (0.0.8, different author). The
  tool is `@memi-design/cli`.
- Do NOT re-evaluate on `diagnose` alone. `craft audit` and `ux audit` score the
  same file differently, so a single subcommand is not the tool.
- Do NOT treat a memi score as a signal without a finding under it. Both pages
  scored while reporting zero or one issue, and most dimensions unassessed.
- It writes reports into `.memoire/app-quality/` in the CWD. That directory was
  removed after this evaluation; it is not gitignored because nothing should be
  producing it.
